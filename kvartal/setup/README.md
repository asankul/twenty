# Установщик настройки кабинета

Настройка Квартала собиралась больше месяца десятками правок и живёт только
в боевой базе. В `/opt/twenty` лежат 35 файлов SQL, где отменённые
вперемешку с действующими — по ним невозможно сказать, каким набором шагов
получается текущее состояние.

Отсюда две задачи, которые решает этот каталог:

1. **Поднять второй кабинет** так же, как настроен первый.
2. **Восстановить первый**, если база погибнет. Сегодня такой возможности нет.

Всё здесь **снимается с живой базы скриптами**, а не пишется по памяти.
Единственный достоверный источник — сама база.

## Что уже есть

| Файл | Что это |
|---|---|
| `extract.sh` | снимает с живой базы функции и триггеры флоу |
| `install.sh` | ставит шаги по порядку на схему указанного кабинета |
| `03_flow.sql` | 12 функций `ops` и 9 триггеров — веса, нормативы, исходы |
| `fields.json` | опись 42 наших полей на заявке, задаче, контакте и сотруднике |
| `stage.json` | 10 стадий воронки |

### Как снимать и ставить

```bash
PSQL="ssh -i ~/.ssh/twenty-deploy root@HOST docker exec -i twenty-db-1 psql -U postgres -d default" \
  ./extract.sh workspace_d23hh7a34snje4p8trbenc2ot

PSQL="docker exec -i twenty-db-1 psql -U postgres -d default" \
  ./install.sh workspace_НОВОГО_КАБИНЕТА
```

`docker exec` обязательно с `-i`: запросы уходят в stdin, потому что по
дороге к боевой базе стоит ещё один шелл и он бы разорвал многострочный SQL.

### Что проверено

`03_flow.sql` прогнан на одноразовой базе со структурой прода: заявка
заводится, задача получает вес 50, исход «Думает» её закрывает, стадия
уезжает в «Квалифицированные», рождается «Перезвонить» через 2 дня весом
70. Отказ без причины отбит, галочка без итога отбита.

### Почему поля нельзя поставить одним SQL

Среди наших 66 добавлений есть не только поля, но и **свой объект
`taskComment`** — со своей таблицей, стандартным набором полей и
морф-связями на пяти других объектах. Собрать такое голым SQL и не
ошибиться нереально.

Поэтому метаданные (объекты, поля, списки значений) надо ставить через
**родной API метаданных Twenty** — тот же, которым пользуется интерфейс.
Он создаст объект, поля и связи согласованно. SQL остаётся для того, чего
API не умеет: функции и триггеры флоу, подмена списка значений у
стандартного поля `stage`, права и построчные правила.

## Важное ограничение

Функции лежат в общей схеме `ops`, а имя схемы кабинета вшито в их тела.
**Два кабинета в одной базе затрут функции друг друга.** Поэтому у каждого
кабинета должна быть своя база — либо, если понадобится многокабинетный
режим, функции придётся разносить по схемам вида `ops_<кабинет>`.
